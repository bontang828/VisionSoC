# Driver Implementation Handoff (KV260)

**Audience:** future programmer or AI agent (Codex, Claude) implementing
the ARM-side driver and main image-processing program on AMD Kria KV260
running Ubuntu Server 24.04 LTS. This is the **how-to-build** companion
to `fyp_doc/2d_fabric_fpga_design_handoff.md` (design rationale doc).
Read the design doc first; this one is a prescriptive task list.

This doc tells you exactly **which files to create, what each function
should do, and which build commands to run**. It does NOT re-explain
why each choice was made.

> **Required reading before writing code:**
>
>   1. `fyp_doc/2d_fabric_handoff.md` — T1 programming model (the "stock
>      RVV intuitions break here" doc). RVV instructions issued through
>      the wrapper run on the 2D fabric, not stock RVV.
>   2. `fyp_doc/2d_fabric_fpga_design_handoff.md` — design overview;
>      explains why the doc you're reading now exists.
>   3. `fyp_doc/fpga_implementation_handoff.md` — what the FPGA side
>      must look like. The driver depends on its register map.
>   4. `tests/vision_task/benchmark_vadd.c` lines 5–305 and
>      `benchmark_instructions.c` lines 5–90 — the RVV programmer rules
>      R1–R8.

## 0. Scope and prerequisites

You are building three things:

  1. **`libt1`** — a userspace C library that exposes a clean API for
     issuing RVV instructions to T1 over AXI Lite via UIO.
  2. **`build_kernel.sh`** — a helper script that converts a `.S` RVV
     assembly file into a `kernel.h` containing a `static const uint32_t
     kernel[]` byte array.
  3. **`visionsoc_main`** — an example main program that ties libt1 +
     V4L2 capture + DRM display + AXI DMA prefetch into a real-time
     camera→T1→HDMI pipeline.

You do **not** need to write any kernel-mode code. UIO + V4L2 + DRM
already provide everything from userspace.

### 0.1 Prerequisites on the Kria

```sh
sudo apt update
sudo apt install -y \
    build-essential \
    binutils-riscv64-linux-gnu \
    libdrm-dev \
    v4l-utils \
    device-tree-compiler \
    udmabuf-utils \
    xlnx-firmware-kv260-smartcam   # reference for camera DT
```

### 0.2 What the FPGA side must provide

You depend on the FPGA side already being done per
`fyp_doc/fpga_implementation_handoff.md`:

  * `system_top_wrapper.bit` loaded via `fpgautil -b ...`.
  * `system_top_wrapper.dtbo` declaring `compatible = "generic-uio"`
    for the T1 wrapper at `0xA0000000` and the AXI DMA at `0xA0010000`.
  * `/dev/uio0` (T1) and `/dev/uio1` (DMA) appear after overlay load.
  * AP1302 V4L2 driver loaded → `/dev/video0` works.
  * DRM HDMI sink reachable via libdrm.

If any of these are missing, **stop and fix the FPGA side first**.

## 2. Register map — `libt1_regs.h`

Single source of truth for register offsets. **This file must match
the FPGA-side wrapper** (`fpga/wrapper/t1_axi_lite_wrapper.sv`) exactly.
If they ever drift, the driver silently corrupts. Lock these values.

```c
#pragma once
#include <stdint.h>

// Wrapper register offsets (relative to the AXI Lite BAR base 0xA0000000)
#define T1_REG_CTRL              0x00
#define T1_REG_INSTRUCTION       0x04
#define T1_REG_RS1_DATA          0x08
#define T1_REG_RS2_DATA          0x0C
#define T1_REG_VTYPE             0x10
#define T1_REG_VL                0x14
#define T1_REG_VSTART            0x18
#define T1_REG_VCSR              0x1C
#define T1_REG_RD_FIFO_STS       0x20
#define T1_REG_RD_POP_DATA       0x24
#define T1_REG_RD_POP_META       0x28
#define T1_REG_CSR_FIFO_STS      0x2C
#define T1_REG_CSR_POP           0x30
#define T1_REG_CSR_FFLAG         0x34
#define T1_REG_MEM_COUNT         0x38
#define T1_REG_IRQ_EN            0x3C
#define T1_REG_IRQ_STATUS        0x40
#define T1_REG_VERTICAL_MODE     0x44
#define T1_REG_PERF_TAG          0x48
#define T1_REG_PERF_DELTA        0x4C
#define T1_REG_PERF_CYCLES_LO    0x50
#define T1_REG_PERF_CYCLES_HI    0x54

// CTRL bits
#define T1_CTRL_ISSUE_START      (1u << 0)   // W1S
#define T1_CTRL_ISSUE_READY      (1u << 1)   // RO
#define T1_CTRL_ISSUE_BUSY       (1u << 2)   // RO

// IRQ_EN / IRQ_STATUS bits
#define T1_IRQ_RD                (1u << 0)
#define T1_IRQ_CSR               (1u << 1)
#define T1_IRQ_MEM               (1u << 2)

// AXI DMA register offsets (relative to 0xA0010000)
// Standard Xilinx AXI DMA layout — see PG021. Subset used here:
#define DMA_REG_MM2S_CR          0x00
#define DMA_REG_MM2S_SR          0x04
#define DMA_REG_MM2S_SRC_ADDR    0x18
#define DMA_REG_MM2S_LENGTH      0x28
#define DMA_REG_S2MM_CR          0x30
#define DMA_REG_S2MM_SR          0x34
#define DMA_REG_S2MM_DST_ADDR    0x48
#define DMA_REG_S2MM_LENGTH      0x58
#define DMA_CR_RUN               (1u << 0)
#define DMA_CR_RESET             (1u << 2)
#define DMA_CR_IOC_IRQ_EN        (1u << 12)
#define DMA_SR_IDLE              (1u << 1)
#define DMA_SR_IOC_IRQ           (1u << 12)
```

## 3. Public API — `libt1.h`

```c
#pragma once
#include <stdint.h>
#include <stddef.h>
#include <stdbool.h>

// Issue payload for one RVV instruction.
struct t1_op {
    uint32_t instruction;       // 32-bit RVV encoding
    uint32_t rs1, rs2;          // scalar operands; PA for memory ops
    uint32_t vtype;             // standard RVV vtype
    uint32_t vl;                // vector length (== 128 for full grid)
    uint32_t vstart;            // usually 0
    uint32_t vcsr;              // vxrm[2:1], vxsat[0]
    uint8_t  vertical_mode;     // 0 = horizontal, 1 = vertical
};

// Lifecycle.
int  t1_init(void);
void t1_close(void);

// Issue — blocks via IRQ until T1 retires the instruction.
// Returns 0 on success, -1 on error (errno set).
int  t1_issue(const struct t1_op *op);

// Issue a stream of pre-assembled instructions (Style B).
// `kernel` is a uint32_t[] from build_kernel.sh; same vtype/vl
// applied to all unless overridden by an embedded vsetvli in the asm.
// `op_template` provides rs1, rs2, vertical_mode, etc.
int  t1_issue_kernel(const uint32_t *kernel, size_t n_words,
                     const struct t1_op *op_template);

// Pop the rd FIFO (results from vmv.x.s, vfmv.f.s, etc.).
// Returns 1 if popped, 0 if empty.
int  t1_drain_rd(uint32_t *data, uint8_t *rd_addr, bool *is_fp);

// Wait for n vse memory-retire events.
int  t1_wait_mem(unsigned n_events);

// Perf counters.
uint32_t t1_perf_start(uint8_t tag);    // writes PERF_TAG; returns LO cycles
uint32_t t1_perf_stop(void);            // writes 0; returns delta
uint64_t t1_cycles(void);               // 64-bit free-running PL counter

// DMA prefetch (uses /dev/uio1).
// Sync = block until done; Async = kick and return.
int  t1_dma_mm2s_sync(uint32_t src_pa, uint32_t dst_pa, uint32_t len);
int  t1_dma_s2mm_sync(uint32_t src_pa, uint32_t dst_pa, uint32_t len);
int  t1_dma_mm2s_async(uint32_t src_pa, uint32_t dst_pa, uint32_t len);
int  t1_dma_s2mm_async(uint32_t src_pa, uint32_t dst_pa, uint32_t len);
int  t1_dma_wait(void);

// Memory allocation (udmabuf wrapper).
struct t1_buf {
    void    *va;
    uint32_t pa;
    size_t   size;
    int      _udmabuf_fd;
};
int  t1_buf_alloc(struct t1_buf *buf, size_t size);
void t1_buf_free(struct t1_buf *buf);

// Helper: VA → PA via /proc/self/pagemap. Use only if you can't
// allocate via t1_buf_alloc (which is preferred — it gives you the
// PA directly).
uint32_t t1_va_to_pa(const void *va);
```

## 4. Implementation — `libt1.c`

### 4.1 Module-state

```c
static int      g_uio_t1_fd  = -1;
static int      g_uio_dma_fd = -1;
static volatile uint32_t *g_t1_regs  = NULL;   // mmap'd 0xA0000000
static volatile uint32_t *g_dma_regs = NULL;   // mmap'd 0xA0010000
```

### 4.2 `t1_init()`

```c
int t1_init(void) {
    g_uio_t1_fd = open("/dev/uio0", O_RDWR | O_CLOEXEC);
    if (g_uio_t1_fd < 0) return -1;

    g_t1_regs = mmap(NULL, 4096, PROT_READ | PROT_WRITE, MAP_SHARED,
                     g_uio_t1_fd, 0);
    if (g_t1_regs == MAP_FAILED) { /* close + return */ }

    g_uio_dma_fd = open("/dev/uio1", O_RDWR | O_CLOEXEC);
    if (g_uio_dma_fd < 0) { /* clean up */ }

    g_dma_regs = mmap(NULL, 4096, PROT_READ | PROT_WRITE, MAP_SHARED,
                      g_uio_dma_fd, 0);
    if (g_dma_regs == MAP_FAILED) { /* clean up */ }

    // Enable mem IRQ by default; rd/csr enabled lazily.
    g_t1_regs[T1_REG_IRQ_EN / 4] = T1_IRQ_MEM;

    return 0;
}
```

> Note: `T1_REG_*` are byte offsets; `g_t1_regs` is a `uint32_t*` so
> divide by 4. Pick one convention (volatile uint32_t pointer vs
> `mmio_read/write` macros on `uint8_t*`) and be consistent.

### 4.3 `t1_issue()`

```c
int t1_issue(const struct t1_op *op) {
    // 1. Wait until T1 is ready (rare — the wrapper de-asserts ready
    //    only briefly between issues, so this is usually a single read).
    while (!(g_t1_regs[T1_REG_CTRL / 4] & T1_CTRL_ISSUE_READY)) {
        // could yield via sched_yield(); typical wait is sub-µs
    }

    // 2. Write all operand registers.
    g_t1_regs[T1_REG_INSTRUCTION   / 4] = op->instruction;
    g_t1_regs[T1_REG_RS1_DATA      / 4] = op->rs1;
    g_t1_regs[T1_REG_RS2_DATA      / 4] = op->rs2;
    g_t1_regs[T1_REG_VTYPE         / 4] = op->vtype;
    g_t1_regs[T1_REG_VL            / 4] = op->vl;
    g_t1_regs[T1_REG_VSTART        / 4] = op->vstart;
    g_t1_regs[T1_REG_VCSR          / 4] = op->vcsr;
    g_t1_regs[T1_REG_VERTICAL_MODE / 4] = op->vertical_mode ? 1 : 0;

    // 3. Snapshot mem_count before kicking, so we know when retire
    //    happens.
    uint32_t pre_mem = g_t1_regs[T1_REG_MEM_COUNT / 4];

    // 4. Kick.
    g_t1_regs[T1_REG_CTRL / 4] = T1_CTRL_ISSUE_START;

    // 5. For LSU instructions (vle/vse), wait for mem_count to bump.
    //    For non-LSU, just spin briefly until issue_busy clears.
    if (is_lsu_instruction(op->instruction)) {
        wait_mem_irq_or_count(pre_mem + 1);
    } else {
        // Compute ops have no mem retire; wait for issue_busy=0
        while (g_t1_regs[T1_REG_CTRL / 4] & T1_CTRL_ISSUE_BUSY) { }
    }

    return 0;
}
```

`is_lsu_instruction()` is a small decoder that checks the opcode bits
of `op->instruction`. RVV memory ops have major opcode `0x07` (load) or
`0x27` (store). Inspect `instruction[6:0]`:

```c
static bool is_lsu_instruction(uint32_t instr) {
    uint32_t opcode = instr & 0x7F;
    return (opcode == 0x07) || (opcode == 0x27);
}
```

`wait_mem_irq_or_count()` blocks via `read(g_uio_t1_fd, ...)` and
re-arms the IRQ on each wake — UIO requires a write to `/dev/uioN` to
re-arm. Decrement `MEM_COUNT` (W1C bit[0] at 0x38) when consumed.

### 4.4 `t1_issue_kernel()`

```c
int t1_issue_kernel(const uint32_t *kernel, size_t n_words,
                    const struct t1_op *op_template) {
    struct t1_op op = *op_template;
    for (size_t i = 0; i < n_words; i++) {
        op.instruction = kernel[i];
        if (t1_issue(&op) < 0) return -1;
    }
    return 0;
}
```

### 4.5 Perf helpers

```c
uint32_t t1_perf_start(uint8_t tag) {
    g_t1_regs[T1_REG_PERF_TAG / 4] = tag;
    return g_t1_regs[T1_REG_PERF_CYCLES_LO / 4];
}

uint32_t t1_perf_stop(void) {
    g_t1_regs[T1_REG_PERF_TAG / 4] = 0;
    return g_t1_regs[T1_REG_PERF_DELTA / 4];
}

uint64_t t1_cycles(void) {
    // Two-read, retry-if-overflow pattern.
    uint32_t hi1 = g_t1_regs[T1_REG_PERF_CYCLES_HI / 4];
    uint32_t lo  = g_t1_regs[T1_REG_PERF_CYCLES_LO / 4];
    uint32_t hi2 = g_t1_regs[T1_REG_PERF_CYCLES_HI / 4];
    if (hi1 != hi2) {
        // Overflow during read; retry — second read is reliable
        lo = g_t1_regs[T1_REG_PERF_CYCLES_LO / 4];
    }
    return ((uint64_t)hi2 << 32) | lo;
}
```

### 4.6 udmabuf allocator

```c
int t1_buf_alloc(struct t1_buf *buf, size_t size) {
    char path[64];
    static int next_idx = 0;
    snprintf(path, sizeof(path), "/dev/udmabuf%d", next_idx++);
    int fd = open(path, O_RDWR | O_CLOEXEC);
    if (fd < 0) return -1;

    buf->va = mmap(NULL, size, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
    if (buf->va == MAP_FAILED) { close(fd); return -1; }

    // Read PA from sysfs
    char sysfs[128];
    snprintf(sysfs, sizeof(sysfs),
             "/sys/class/u-dma-buf/udmabuf%d/phys_addr", next_idx - 1);
    FILE *f = fopen(sysfs, "r");
    if (!f) { munmap(buf->va, size); close(fd); return -1; }
    unsigned long long pa;
    fscanf(f, "0x%llx", &pa);
    fclose(f);

    buf->pa = (uint32_t)pa;
    buf->size = size;
    buf->_udmabuf_fd = fd;
    return 0;
}
```

> Setup: at boot time, `modprobe u-dma-buf` and create the udmabuf
> instance(s) with the right size, e.g.:
>
> ```sh
> sudo modprobe u-dma-buf udmabuf0=65536
> ```
>
> or via `/sys/class/u-dma-buf/.../sync_mode` (consult u-dma-buf docs).

### 4.7 DMA helpers

```c
int t1_dma_mm2s_async(uint32_t src_pa, uint32_t dst_pa, uint32_t len) {
    g_dma_regs[DMA_REG_MM2S_CR / 4]       = DMA_CR_RUN | DMA_CR_IOC_IRQ_EN;
    g_dma_regs[DMA_REG_MM2S_SRC_ADDR / 4] = src_pa;
    g_dma_regs[DMA_REG_MM2S_LENGTH / 4]   = len;  // kicks the txfr
    return 0;
}

int t1_dma_wait(void) {
    uint32_t irq_count;
    int n = read(g_uio_dma_fd, &irq_count, 4);
    if (n != 4) return -1;
    // Clear IRQ status, re-arm by writing 1 to /dev/uio1
    uint32_t one = 1;
    write(g_uio_dma_fd, &one, 4);
    return 0;
}
```

> The exact AXI DMA register sequence is documented in Xilinx PG021.
> Adapt the above template if you discover edge cases (e.g. needing
> to clear MM2S_SR.IOC bit before re-arming).

## 5. Weight format — `weights_format.h`

```c
#pragma once
#include <stdint.h>

// Weights live in a reserved DDR region (e.g. 0x70020000). One file
// per layer, copied in by a systemd unit at boot.
// Layout: row-major, contiguous, 128-byte aligned (one T1 row = 128
// elements at SEW=8).
//
// Per-layer file: weights_layer_N.bin
// Size in bytes:  out_ch * in_ch * kH * kW

struct weights_layer_descriptor {
    uint32_t pa;        // physical address of the layer's start
    uint32_t out_ch;
    uint32_t in_ch;
    uint32_t kH, kW;
    int8_t   scale;     // optional per-layer dequant scale
    int8_t   zero_pt;   // optional per-layer zero point
};

// Recommended convention: an array of these descriptors lives in a
// JSON sidecar (weights_manifest.json) loaded at startup.
```

## 6. Kernel build — `build_kernel.sh`

```sh
#!/usr/bin/env bash
# build_kernel.sh kernel.S kernel.h kernel_name
#
# Assembles a RV32V .S file and emits a C header containing
# `static const uint32_t <kernel_name>[]`.
set -e

SRC=$1
DST=$2
NAME=$3

if [ -z "$SRC" ] || [ -z "$DST" ] || [ -z "$NAME" ]; then
    echo "Usage: $0 <kernel.S> <kernel.h> <kernel_name>"
    exit 1
fi

TMP=$(mktemp -d)
trap "rm -rf $TMP" EXIT

riscv64-linux-gnu-as -march=rv32imafc_zvl256b "$SRC" -o "$TMP/kernel.o"
riscv64-linux-gnu-objcopy -O binary -j .text "$TMP/kernel.o" "$TMP/kernel.bin"

{
    echo "// Auto-generated from $SRC by build_kernel.sh"
    echo "// Do not edit; regenerated each build"
    echo "#pragma once"
    echo "#include <stdint.h>"
    printf "static const uint32_t %s[] = {\n    " "$NAME"
    od -An -tx4 -w16 "$TMP/kernel.bin" | \
        awk '{ for (i=1; i<=NF; i++) printf "0x%s, ", $i; print "" }'
    echo "};"
    echo "static const uint32_t ${NAME}_count = sizeof($NAME)/4;"
} > "$DST"

echo "Wrote $DST"
```

Invoke:

```sh
./build_kernel.sh kernels/grid_vadd.S kernels/grid_vadd.h grid_vadd
```

Example `kernels/grid_vadd.S`:

```asm
# Vector add kernel — ports tests/vision_task/simple_instruction_asm.c
# rs1 = grid_a PA, rs2 = grid_b PA — but on KV260 driver passes both
# as separate t1_op fields. Here the asm just executes pre-set
# operands; the driver fills rs1/rs2 between issues if the kernel
# requires multiple loads.
.text
.global _kernel
_kernel:
    vsetvli zero, x0, e8, m4, ta, ma   # x0 here is taken from t1_op.vl=128
    vle8.v  v8, (x0)                    # rs1 from t1_op
    vle8.v  v12, (x0)                   # need a second load — use a
                                         # different t1_op rs1 path
    vsub.vv v8, v8, v12
    vse8.v  v8, (x0)                    # rs1 = output PA
```

> The kernel asm contains the **opcode encoding only** — operands
> like `rs1`/`rs2` come from the `t1_op` struct at issue time, not from
> the asm. So a single kernel file represents a *fixed instruction
> sequence* with placeholder register references that the driver
> resolves. For multi-stage kernels that need different rs1 per
> instruction (e.g. `vle8 v8, (a)` then `vle8 v12, (b)`), the driver
> issues each instruction separately with the correct `rs1`.

## 7. Tests — `vision_software/libt1/test/`

### 7.1 `smoke.c` — wrapper accessibility

```c
int main(void) {
    if (t1_init() < 0) { perror("t1_init"); return 1; }

    // Free-running counter must advance.
    uint64_t c0 = t1_cycles();
    usleep(10000);
    uint64_t c1 = t1_cycles();
    printf("cycles advanced by %llu in 10ms\n",
           (unsigned long long)(c1 - c0));
    if (c1 - c0 < 100000) {
        fprintf(stderr, "FAIL: counter did not advance\n");
        return 1;
    }

    // VERTICAL_MODE round-trip.
    struct t1_op op = {
        .instruction   = 0x00000013,  // nop (addi x0,x0,0) — won't issue,
                                       // just probe
        .vertical_mode = 1
    };
    // (don't actually issue; just write the reg via a private
    // helper to confirm writability.)
    t1_set_vertical_mode_raw(1);
    if (t1_get_vertical_mode_raw() != 1) {
        fprintf(stderr, "FAIL: VERTICAL_MODE write not visible\n");
        return 1;
    }
    t1_set_vertical_mode_raw(0);

    printf("PASS\n");
    t1_close();
    return 0;
}
```

### 7.2 `ddr_roundtrip.c` — vle + vse

```c
int main(void) {
    t1_init();

    struct t1_buf in_buf, out_buf;
    t1_buf_alloc(&in_buf, 16384);   // 128*128
    t1_buf_alloc(&out_buf, 16384);

    int8_t *in = (int8_t*)in_buf.va;
    int8_t *out = (int8_t*)out_buf.va;
    for (int i = 0; i < 16384; i++) in[i] = (int8_t)(i & 0x7f);
    memset(out, 0, 16384);

    // vsetvli zero, 128, e8, m4, ta, ma
    struct t1_op vsetvli = {
        .instruction = 0xc01077d7,  // example encoding — verify with
                                     // riscv64-linux-gnu-objdump
        .vtype = 0x0a,  // SEW=8, LMUL=4
        .vl    = 128,
    };
    t1_issue(&vsetvli);

    // vle8.v v8, (rs1)
    struct t1_op vle = {
        .instruction = 0x02050407,  // vle8.v v8, (a0) — confirm enc
        .rs1 = in_buf.pa,
        .vtype = 0x0a,
        .vl    = 128,
    };
    t1_issue(&vle);

    // vse8.v v8, (rs1)
    struct t1_op vse = {
        .instruction = 0x02050427,  // vse8.v v8, (a0)
        .rs1 = out_buf.pa,
        .vtype = 0x0a,
        .vl    = 128,
    };
    t1_issue(&vse);
    t1_wait_mem(1);

    // Compare
    int errs = memcmp(in, out, 16384);
    printf("%s: roundtrip\n", errs ? "FAIL" : "PASS");

    t1_buf_free(&in_buf);
    t1_buf_free(&out_buf);
    t1_close();
    return errs ? 1 : 0;
}
```

> Confirm instruction encodings with
> `riscv64-linux-gnu-objdump -d kernel.o` after assembling a sample.
> Don't hard-code the hex above without verification.

## 9. Main program — `visionsoc_main/main.c`

The example brings together camera capture, T1 processing, scratchpad
DMA, and HDMI output. Write each subsystem in its own file
(`camera.{c,h}`, `display.{c,h}`, `dma.{c,h}`) and orchestrate from
`main.c`.

### 9.1 Skeleton

```c
#include "libt1.h"
#include "camera.h"
#include "display.h"
#include "kernels/grid_vadd.h"

#define BRAM_BASE_PA  0xB0000000u
#define BRAM_HALF_A   (BRAM_BASE_PA + 0x0000)
#define BRAM_HALF_B   (BRAM_BASE_PA + 0x4000)
#define FRAME_BYTES   (128 * 128)

int main(void) {
    if (t1_init() < 0) die("t1_init");

    struct camera cam;
    struct display disp;
    if (camera_open(&cam, "/dev/video0", 128, 128) < 0) die("camera_open");
    if (display_open(&disp) < 0) die("display_open");

    int half = 0;
    uint32_t frame_count = 0;
    uint64_t t0 = t1_cycles();

    while (1) {
        // 1. DQBUF capture frame from camera (V4L2)
        struct camera_buf cb;
        camera_dqbuf(&cam, &cb);

        // 2. Kick DMA: copy frame from camera buffer to BRAM half (current half).
        uint32_t bram_half = (half == 0) ? BRAM_HALF_A : BRAM_HALF_B;
        t1_dma_mm2s_sync(cb.pa, bram_half, FRAME_BYTES);

        // 3. Run kernel on the BRAM half.
        struct t1_op tmpl = {
            .vtype = 0x0a,           // SEW=8, LMUL=4
            .vl    = 128,
            .rs1   = bram_half,      // input + output (in-place)
            .rs2   = 0,
            .vertical_mode = 0,
        };
        t1_perf_start(/*tag=*/1);
        t1_issue_kernel(grid_vadd, grid_vadd_count, &tmpl);
        uint32_t kernel_cycles = t1_perf_stop();

        // 4. DMA result back: BRAM half → display buf
        struct display_buf db;
        display_dq_for_filling(&disp, &db);
        t1_dma_s2mm_sync(bram_half, db.pa, FRAME_BYTES);

        // 5. Page-flip
        display_qbuf(&disp, &db);
        camera_qbuf(&cam, &cb);

        half = !half;
        frame_count++;

        if ((frame_count & 0x1f) == 0) {
            uint64_t t1c = t1_cycles();
            printf("frame %u, last kernel = %u cycles, %.1f fps\n",
                   frame_count, kernel_cycles,
                   32.0 * 1e9 / ((double)(t1c - t0) / 80e6 * 1e9));
            t0 = t1c;
        }
    }

    camera_close(&cam);
    display_close(&disp);
    t1_close();
    return 0;
}
```

### 9.2 `camera.{c,h}` — V4L2 wrapper

Standard V4L2 user pointer / dma-buf flow:

  * `VIDIOC_S_FMT` for 128×128 YUV (or whatever the AP1302 V4L2 subdev
    presents after `vpss_down` scales). Use `media-ctl --print-topology`
    to inspect the pipeline.
  * `VIDIOC_REQBUFS` × 4 with `V4L2_MEMORY_MMAP` or `_DMABUF`.
  * `VIDIOC_QBUF` to enqueue, `VIDIOC_DQBUF` to dequeue (blocking;
    triggers IRQ from frmbuf_wr).
  * `VIDIOC_STREAMON` to start, `VIDIOC_STREAMOFF` to stop.

Reference: AMD's `kv260-smartcam` userspace already has this loop —
adapt directly.

### 9.3 `display.{c,h}` — DRM wrapper

  * `drmOpen("/dev/dri/card0")` (KV260 carrier card).
  * `drmModeCreateDumb` for each display buffer.
  * `drmModeAddFB2WithModifiers` to register.
  * `drmModePageFlip` per frame.

Or use the simpler V4L2 approach with `kmssink` from gstreamer if you
don't need fine-grained control. For the bringup this is fine.

### 9.4 `dma.{c,h}` — already provided by libt1

The DMA helpers live in libt1. `dma.{c,h}` is a thin shim if you want
domain-specific helpers (e.g. `prefetch_next_frame`).

## 10. Bringup sequence — order matters

Follow these in order. Each step depends on all previous ones working.

  1. **FPGA side complete.** `system_top_wrapper.bit` boots, `/dev/uio0`
     and `/dev/uio1` exist. (See `fpga_implementation_handoff.md`.)
  2. **`smoke.c` passes.** Confirms wrapper accessibility,
     `PERF_CYCLES` advances, `VERTICAL_MODE` is RW.
  3. **`ddr_roundtrip.c` passes.** Confirms udmabuf works, AXI Lite
     issue path works, T1 LSU executes correctly, HPC0 coherence is
     real.
  4. **`port_grid_vadd.c` passes.** Confirms Style B (kernel byte
     array) end-to-end. Compare output bytewise against the simulator's
     expected output for the same kernel.
  5. **Vertical mode regression.** Port a kernel from
     `tests/vision_task/simple_instruction_vert_lsu.c`. Confirm
     transpose behaviour. **This is the gate** that proves the
     wrapper VERTICAL_MODE plumbing works end-to-end.
  6. **Camera bringup standalone.** No T1. Run gstreamer:
     ```sh
     gst-launch-1.0 -v v4l2src device=/dev/video0 ! videoconvert ! kmssink
     ```
     Expect live camera on the HDMI monitor.
  7. **DMA path standalone.** Use `t1_dma_mm2s_sync` to copy 16 KB
     from one udmabuf to another; bytewise-compare. Confirms DMA
     descriptor logic.
  8. **Full pipeline.** Wire 1–7 together in `main.c`. Measure FPS
     with `t1_cycles()`; expect ≥30 fps for a few-instruction kernel.
     Tune kernel size if needed; § 2.6 of design doc says the budget
     is comfortable.

### 10.1 Debugging — common failures

The order below mirrors the order things go wrong during the bringup
sequence in § 10. If you're stuck on step N, check the matching
sub-section.

#### 10.1.1 `t1_init` returns -1 with `ENOENT`
  * **Cause:** UIO devices missing. FPGA overlay didn't load, or DTS
    didn't declare them as `generic-uio`.
  * Check: `ls /dev/uio*` — should show `/dev/uio0` (T1 wrapper) and
    `/dev/uio1` (DMA).
  * Check: `dmesg | grep uio` for binding errors.
  * Fix: this is an FPGA-side problem; see
    `fyp_doc/fpga_implementation_handoff.md` § 8.4.1.

#### 10.1.2 `smoke.c` fails: counter doesn't advance
  * **Cause:** wrapper not seeing `aclk`; FPGA-side problem.
  * Verify: `sudo devmem2 0xa0000050 w` advances between calls.
    If it doesn't, fix FPGA side (§ 8.4.2 of fpga_impl) before
    continuing driver work.

#### 10.1.3 `t1_issue` hangs forever
  * **Most likely:** IRQ never raises. Either the kernel issued is a
    pure-compute instruction (no `vse`) so `MEM_COUNT` won't bump and
    `IRQ_EN[2]`-only setup will never wake.
  * Diagnostic from another shell while the program is hung:
    ```sh
    sudo devmem2 0xa0000040 w   # IRQ_STATUS — what's pending?
    sudo devmem2 0xa0000038 w   # MEM_COUNT — did vse retire?
    sudo devmem2 0xa0000020 w   # RD_FIFO_STS — is rd FIFO non-empty?
    sudo devmem2 0xa000002c w   # CSR_FIFO_STS
    sudo devmem2 0xa0000000 w   # CTRL — is issue_busy still set?
    ```
  * If CTRL.issue_busy is still set: T1 has not retired the
    instruction. Likely an LSU stall (bad PA, AXI hang).
  * If MEM_COUNT didn't increment: the kernel didn't have a `vse`;
    enable `IRQ_EN[0]` (rd) and use `t1_drain_rd()` instead, or just
    poll `CTRL.issue_busy` for compute-only ops.
  * Fix: revisit § 4.3's `is_lsu_instruction()` and make sure the
    wait path matches the kernel.

#### 10.1.4 `ddr_roundtrip.c` shows wrong bytes (most-recent ARM write missing)
  * **Most likely:** cache coherence. ARM dirty lines aren't visible
    to T1 because the FPGA wired T1's HBM master to HP0 (non-coherent)
    instead of HPC0 (coherent).
  * Check: in the FPGA build, `system_top.tcl` should connect
    `t1_top/m_axi_hb` → `S_AXI_HPC0_FPD` (not HP0/HP1/HP2).
  * Workaround in the driver: add an explicit cache flush before
    `t1_issue` of any `vle`. Linux userspace doesn't have a clean
    API for this — easiest is `msync(buf->va, buf->size, MS_SYNC)`
    on the udmabuf, which is enough for `dma-coherent`-marked
    udmabuf regions.
  * Real fix: re-route HBM master to HPC0.

#### 10.1.5 `port_grid_vadd.c` produces garbage output
  * **Most likely:** instruction encodings hand-written wrong. Don't
    hand-encode RVV — use the Style B build flow.
  * Diagnostic: assemble the kernel via
    ```sh
    riscv64-linux-gnu-as -march=rv32imafc_zvl256b kernel.S -o /tmp/k.o
    riscv64-linux-gnu-objdump -d /tmp/k.o
    ```
    Compare the bytes against what your driver is sending.
  * Or print the `kernel[]` array your driver issues and verify
    instruction-by-instruction.

#### 10.1.6 Vertical-mode regression fails (transpose doesn't appear)
  * **Most likely:** `VERTICAL_MODE` register is being written but the
    bit isn't reaching T1.
  * Check from another shell:
    ```sh
    sudo devmem2 0xa0000044 w 0x1
    sudo devmem2 0xa0000044 w   # should read 0x1
    ```
    If it doesn't round-trip, FPGA wrapper bug — see § 8.4.3 of
    fpga_impl.
  * If it round-trips but kernels still don't transpose: the
    `gen_wrapper.sh` template wasn't updated to thread
    `issue_bits_verticalMode` from wrapper to T1 — see § 8.4.8 of
    fpga_impl.

#### 10.1.7 udmabuf PA mismatch / kernel reads zeros
  * **Most likely:** reading PA from the wrong sysfs path; or udmabuf
    not actually CMA-backed (so PA is bogus).
  * Check: `ls /sys/class/u-dma-buf/` — confirm the udmabuf instance
    exists.
  * Check: `cat /sys/class/u-dma-buf/udmabuf0/phys_addr` — should be
    a 64-bit hex starting `0x...`. If it's `0` or empty, the kernel
    module didn't allocate.
  * Check: `dmesg | grep udmabuf` — look for "allocated CMA region"
    or similar.
  * Fix: `modprobe u-dma-buf udmabuf0=65536` at boot via systemd
    (§ 9.5).

#### 10.1.8 V4L2 capture works but image is wrong colour
  * **Most likely:** AP1302 outputs YUV422 but driver assumes RGB or
    pixel layout.
  * Check: `media-ctl --print-topology` — confirm the negotiated
    format on each pad.
  * Fix: `v4l2-ctl --set-fmt-video=width=128,height=128,pixelformat=YUYV`
    (or whatever the AP1302 actually presents).

#### 10.1.9 FPS far below 30
  * **Likely causes, in order:**
    1. DMA serialised on T1 — you're not actually double-buffering;
       check that the prefetch DMA for frame N+1 starts *before*
       the kernel for frame N.
    2. `printf` inside the frame loop — even one `printf` is hundreds
       of µs. Move to deferred logging.
    3. Kernel itself dominates — measure it with `t1_perf_start/stop`
       wrapping just the `t1_issue_kernel` call. If it's >>1 ms,
       shrink the kernel or rebuild bitstream at higher pl_clk0.
    4. UIO IRQ jitter — pin `visionsoc_main` and the IRQ to the same
       core: `taskset 0x4 ./visionsoc_main` and
       `echo 4 > /proc/irq/<n>/smp_affinity`.
  * Diagnostic: instrument every stage with `t1_perf_start/stop` and
    print the deltas — find which stage exceeds the budget.

#### 10.1.10 Cross-reference

The simulator-side programmer rules R1–R8 in
`tests/vision_task/benchmark_vadd.c` lines 36–184 still apply to
kernel asm. § 5 of `fyp_doc/2d_fabric_fpga_design_handoff.md`
explains which rules drop on KV260 (R1/R2/R3 if you stay in Style B)
and which still bite (R4/R5/R7/R8).

## 12. Open items for the implementer

  * **Exact AP1302 V4L2 driver path.** May need `xlnx-firmware-kv260-smartcam`'s
    customised driver bundle, or the upstream `ap1302` driver. Check
    `dmesg` after overlay load.
  * **Instruction encoding table.** Hand-verifying RVV opcode hex is
    error-prone. Maintain a tiny encoder helper (or use
    `riscv64-linux-gnu-objdump -d` on a sample to recover the bytes).
  * **Whether `vsetvli` itself needs to be issued via `t1_issue` or is
    bundled into `vtype`/`vl` register writes.** Currently the wrapper
    has a separate `VTYPE`/`VL` path so `vsetvli` becomes redundant
    once those registers are written — but verify against T1's actual
    behaviour. The wrapper register comment at
    `fpga/wrapper/t1_axi_lite_wrapper.sv:17–18` suggests these are the
    standard RVV `vtype` CSRs sent alongside each instruction.
  * **DMA SG vs simple mode.** § 4.7 assumes simple (non-SG) mode
    matching the existing `system_top.tcl:140` `c_include_sg {0}`. If
    you switch to SG, the API stays but the descriptor handling
    changes.
  * **IRQ pinning / affinity.** For real-time framerate, `taskset`
    `visionsoc_main` to a single core and pin the IRQ to that core
    via `/proc/irq/N/smp_affinity`.

That's the driver side complete. The two implementation handoffs
together (this one + `fpga_implementation_handoff.md`) cover the full
PS↔PL stack.
