A Two-Dimensional RISC-V Vector Fabric for Near-Sensor Vision

FOVEA RVV²

An image is a vector register — 128×128 pixels per instruction.

Load a whole frame with one vle8.v. Every RISC-V Vector instruction is broadcast across a 128-row grid, so a single op touches the entire image. Flip one CSR and rows become columns — for free. Write real CV kernels in plain RVV, with no HDL and no proprietary ISA.

Software For computer-vision researchers
1

An image is a vector register

One vle8.v loads a 128×128 frame across the grid; one vse8.v writes it back. Convolutions, FC layers, matmul, optical flow, even a full int8 CNN are each a few dozen standard RVV instructions — not a Verilog project. If you can write a vector loop, you can program the accelerator.

2

The second dimension is free

A single CSR flip (csrw 0x7c0) turns every horizontal op into a vertical one. Separable filters, on-chip transpose, matmul, and cross-row reductions cost nothing extra. Sobel’s vertical gradient is the exact same code as the horizontal one + one csrw — on stock RVV that needs an explicit transpose.

3

One instruction = thousands of pixel ops

vrgather → 16,384 parallel LUT look-ups in one instruction (gamma / tone-map / activation). Per-row vredsum → 128 dot-products (FC layer / template match / SAD stereo). Native int8 saturating math for quantized inference, and argmax runs on the vector unit — no scalar tournament.

Hardware For hardware engineers
1

128× logical parallelism at ~2-lane cost

The 128-row grid is time-multiplexed over a narrow physical datapath (2 lanes) — you get an image-wide fabric without 16K physical PEs. Built on the open ChipsAlliance T1 vector machine; fully parameterizable vLen / lanes / banks.

2

Conflict-free transpose in the register file

A diagonal-skewed VRF banking scheme scatters bytes so a column (cross-row) access is as cheap as a row access — same SRAM, same cycle. The “vertical mode” is just a read/write permutation: no transpose engine, no ping-pong buffer.

3

FPGA-proven, area-tuned, reproducible

Synthesized & deployed on a Xilinx KV260 (Zynq US+): ~105K LUT (89%), 144/144 BRAM, timing closed (WNS +0.24 ns). vLen=1024 enabled by a MaskUnit area pass (BRAM-backed v0, on-demand slicer, pipelined slide). Full vLen 256→2048 resource sweep characterized.

What works today

End-to-end live SoC on KV260

AR1335 sensor→AP1302 ISP→MIPI CSI-2 →FOVEA / T1 2D fabric→HDMI out

128×128 frames at ~26–30 fps; T1 kernel ≈ 6 ms/frame. Two timing-closed bitstreams: vLen=256 and vLen=1024 (4× register file).

Live demos on the board

Dense optical flow (false-colour motion direction), Sobel edge detect, and camera passthrough — all running on hardware, not just in simulation. On-chip vertical-mode transpose load/store verified end-to-end.
